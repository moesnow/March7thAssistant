# 流程編排使用教程

> 本文件由簡體中文版經 OpenCC 簡繁轉換產生，用語以台灣習慣為準；內容如有差異，請以簡體中文版為準。

## 適合什麼場景

流程編排適合處理下面這類事情：

- 固定介面中的重複點選。
- 需要按條件分支執行的簡單自動化。
- 需要迴圈檢測、切換介面、按鍵、等待、通知等組合動作。
- 想先把零散操作拼成一個可反覆複用的小流程。

如果你的需求已經能被首頁現成任務覆蓋，例如清體力、每日實訓、差分宇宙等，優先使用現成任務即可；

流程編排更適合做“自定義補充邏輯”。

## 基本概念

一個流程由多個步驟組成，步驟以樹狀結構組織。

- 普通步驟：順序執行，例如點選圖片、點選文字、等待、按鍵。
- 滑鼠步驟：支援點選固定座標，也支援按住左鍵從起點滑動到終點。
- 控制步驟：可以包含子步驟，目前支援 `if`、`for`、`while`。
- 迴圈控制步驟：可在迴圈內部使用 `break` 和 `continue`。

你可以把它理解成一個視覺化的“小型指令碼編輯器”，但不需要自己寫程式碼。

## 進入入口

開啟小助手後，進入左側導航欄中的“流程編排”。

介面主要分成兩部分：

- 上半部分：流程列表、執行、停止、匯入匯出、採集模板等操作。
- 下半部分：步驟樹，用來編輯當前流程中的步驟結構。

## 建立第一個流程

### 新建流程

點選“新建流程”，輸入一個容易識別的名稱。

官方示例流程通常是隻讀的，只能檢視，不能直接修改；

你自己新建的流程可以編輯、重新命名、刪除、匯出。

### 新增步驟

點選“新增步驟”可以在當前層級新增一個步驟。

如果當前選中的是 `if`、`for`、`while` 這類控制步驟，還可以點選“新增子步驟”，把新步驟掛到該節點下面。

### 編輯和調整順序

- 雙擊步驟，或者點選“編輯步驟”，可以修改當前步驟。
- 點選“上移”“下移”可以調整同級步驟順序。
- 右鍵步驟樹，可以直接執行整個流程或只執行當前選中步驟。

## 常用步驟說明

### 點選圖片

適合介面上有穩定按鈕、圖示、提示框時使用。

常用配置項：

- 模板路徑：要匹配的圖片素材。
- 圖片閾值：匹配精度。
- 檢測區域：只在指定區域內找圖，可以減少誤識別。
- 重試次數：找不到時重複嘗試的次數。
- 點選動作：點選、按下、鬆開。
- 按下時長：僅在需要長按時填寫；如果留空或為 0，則保持預設點選行為。

### 點選文字

適合按鈕文字比較穩定、但圖示樣式容易變化的場景。

常用配置項：

- 目標文字：OCR 要識別的文字。
- 使用包含匹配：適合目標文字前後可能帶額外內容時使用。
- 檢測區域：限制 OCR 識別範圍。
- 重試次數：找不到時重複嘗試。
- 點選動作、按下時長：與點選圖片相同。

### 點選座標

適合目標位置固定，但沒有穩定圖片或文字可識別的情況。

通常做法是先用截圖工具框出一塊區域，再把該區域座標複製到步驟中。

### 滑動滑鼠

用於在選單中拖動列表，或在遊戲介面中按住左鍵移動滑鼠。

- 滑動起點、滑動終點使用相對遊戲視窗的歸一化座標，例如 `100 / 1920, 540 / 1080`。
- 滑動時長為 0 到 60 秒，決定從起點移動到終點的速度；時長越大，移動越慢。
- 執行時會先移動到起點、按下滑鼠左鍵，移動到終點後再釋放。
- 雲遊戲模式受瀏覽器指標鎖定限制，暫不支援通過該步驟轉動視角；選單拖動仍需在實際遊戲中驗證。

### 查詢圖片 / 查詢文字

這兩類步驟本身不點選，只負責判斷目標是否存在。

它們常用於 `if` 或 `while` 的條件判斷，例如：

- 檢測到“開始挑戰”時才繼續點選。
- 沒檢測到某張提示圖時繼續迴圈等待。

### 等待

最簡單的延時步驟，適合在介面切換、動畫播放、按鈕出現前做緩衝。

### 按下按鍵

用於模擬鍵盤按鍵，可選點選、按下、鬆開，並可配置按鍵時長。

### 切換介面

該步驟會呼叫小助手已有的介面切換邏輯。

可選目標不是任意填寫，而是當前程式中已定義、並且可以從 `main` 主介面主動切換到的介面。

如果某個介面不在下拉式清單裡，說明當前版本不支援直接切過去。

### 播放音訊 / 訊息推送

這兩類步驟適合在關鍵節點提醒你：

- 播放音訊：本地彈出提示音。
- 訊息推送：向你當前配置的通知渠道傳送文本，也可以附帶截圖。

## 控制步驟怎麼用

### if

當條件成立時，執行它下面的子步驟。

適合“如果看到某個按鈕，就點它”這類邏輯。

### for

按固定次數迴圈執行子步驟。

如果迴圈次數填 0，則表示無限迴圈，需要你自己通過條件、停止按鈕或 `break` 來結束。

### while

只要條件仍然成立，就持續執行子步驟。

建議同時設定一個合理的最大迴圈次數，避免條件異常時一直跑不出來。

### break / continue

這兩個步驟只能放在迴圈內部：

- `break`：結束當前迴圈。
- `continue`：跳過本輪後續步驟，直接開始下一輪迴圈。

如果把它們放在迴圈外面，執行日誌裡會提示該步驟無效。

## 如何採集模板和座標

### 採集影像模板

點選“採集影像模板”，程式會開啟截圖視窗。

框選完成後儲存，模板會自動放到當前流程自己的素材目錄裡。

流程素材會跟隨流程一起儲存，匯出流程時也會一併打包。

### 檢測區域怎麼填

如果你已經用截圖工具框過區域，通常可以直接把生成的座標表示式貼上到“檢測區域”。

不填時，預設就是全屏查詢。

為了提高穩定性，建議儘量縮小檢測範圍，只覆蓋目標可能出現的位置。

## 執行與除錯

### 執行流程

點選“執行流程”，會執行當前流程中的全部步驟。

流程現在通過日誌頁的獨立任務執行，因此停止時可以直接在日誌頁強制結束。

### 執行選中步驟

在步驟樹中選中某個步驟後，可以通過右鍵選單執行“執行選中步驟”。

這個功能非常適合除錯某個節點是否能正確識別圖片、文字或座標。

### 日誌怎麼看

執行時建議重點看日誌頁輸出：

- 當前執行到第幾個步驟。
- 條件判斷是否成功。
- 是否達到了最大迴圈次數。
- 是否發生異常、未找到模板、未識別到目標文字等。

## 匯入、匯出與素材目錄

流程以目錄形式儲存，通常包含：

- `workflow.yaml`：流程結構本體。
- `templates/`：圖片模板素材。

你可以使用“匯出流程”把整個流程打成 zip，分享給別人；

也可以通過“匯入流程”恢復到自己的小助手中。

## 一個簡單示例

下面是一個很常見的思路：

1. `if` 檢測文字“開始挑戰”。
2. 條件成立後，子步驟中執行“點選文字：開始挑戰”。
3. `wait` 等待 1 秒。
4. `while` 檢測某個結算提示是否未出現。
5. 迴圈體裡每次等待 1 秒，最多執行若干次。
6. 識別到結算後，播放音訊或傳送訊息。

先把流程做短、做小，確認每個步驟都穩定，再逐步往裡加分支和迴圈，成功率通常更高。

## 常見建議

- 優先使用較小的檢測區域，不要預設全屏找圖或全屏 OCR。
- 圖片模板儘量裁到只保留穩定特徵，避免把動態背景一起截進去。
- 能用文字識別的場景，可以優先嚐試“點選文字”。
- 除錯單個步驟時，優先使用“執行選中步驟”，不要每次都跑完整流程。
- 如果識別結果不穩定，先去“工具箱 → 遊戲截圖”確認程式拿到的畫面是否正確。
- 如果你只是想自動完成現成任務，不建議先從流程編排開始，維護成本會更高。
