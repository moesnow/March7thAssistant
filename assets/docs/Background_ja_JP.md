# バックグラウンド実行

> このドキュメントは簡体字中国語版をもとに AI で翻訳しています。最終更新日: 2026-10-31。差異がある場合は簡体字中国語版を優先してください。

アシスタントがタスクを実行している間もパソコンを使い続けたい場合は、次の 3 つの方法から選べます。

| 方法 | 対象 | キーボードとマウスへの影響 | 設定の難しさ |
|------|------|-----------|---------|
| Windows バックグラウンドモード（推奨） | Windows のローカルゲーム | クリック時に一時的にマウスを借り、終わると返す | 設定で切り替えるだけ |
| クラウド・崩壊：スターレイル | クラウドゲーム | 使用しない | 設定で有効化 |
| リモートローカル多ユーザーデスクトップ（上級者向け） | Windows のローカルゲーム | 現在のデスクトップを使用しない | システムコンポーネントの変更が必要 |

## Windows バックグラウンドモード（推奨）

ゲームウィンドウを他のウィンドウの後ろに置いたまま、アシスタントがウィンドウメッセージでゲームを操作するため、タスク実行中もパソコンを使い続けられます。既定はフォアグラウンドモードのままで、手動で有効にする必要があります。

### 有効にする方法

`設定 → その他 → ローカル操作モード` で `バックグラウンド` を選び、表示される説明を読んで確認すると、次回タスクを開始したときから有効になります。自動会話はいったんオフにしてから再度オンにすると反映されます。

設定ファイルを直接編集することもできます。

```yaml
local_control_mode: background
background_mouse_protection: false
```

クラウドゲームは独自の入力方式を使うため、この設定の影響を受けません。

### 利用条件

- ゲームウィンドウは他のウィンドウの後ろに置けますが、**最小化はできません**。最小化されたウィンドウはキャプチャできず、入力も処理されません。
- 実行中は**システムのロックを解除したまま**にしてください。ロック画面や UAC などのセキュリティで保護されたデスクトップが表示されている間はカーソルを読み書きできないため、バックグラウンド操作は理由を示して停止します。
- ゲームを管理者権限で実行している場合は、アシスタントにも同じ権限が必要です（通常どおり起動したアシスタントは自動で権限を要求します）。
- バックグラウンドモードでは常にウィンドウキャプチャを使います。ウィンドウキャプチャに失敗した場合は認識を停止し、他のアプリが写り込む可能性のあるデスクトップのスクリーンショットには切り替えません。

### マウスとキーボードへの影響

- **クリックとドラッグ**では実際のカーソルを一時的に借り、終わると元の位置に戻します。その間もマウスを動かしていた場合は、その移動分も一緒に戻すため、カーソルはクリック位置に残らず、元の場所で動き続けます。ペンタブレット、タッチスクリーン、リモートデスクトップなどの絶対位置指定デバイスがすでにカーソルを手元に戻している場合は、カーソルを動かしません。
- 操作の前に**マウスが止まるのを待ちます**。押す前に干渉があった場合は最大 3 回再試行し、その後「マウス操作の終了を待機中です。タスクは自動的に再開します」と表示して待機します。タスクは自動的に再開し、通常どおり一時停止や停止もできます。3 ピクセル以内のわずかなぶれは干渉とみなしません。
- **キー入力**は前面のウィンドウやキーボードフォーカスを奪いませんが、ゲームは「アクティブ」な状態でしかキー入力を受け付けないため、バックグラウンドでキーを押すたびにゲームを一時的にアクティブだと認識させます。フィールドの視点では、その間ゲームがカーソルをウィンドウ中央に固定し、キー入力が終わると固定を解除してカーソルを戻します。
- **スクロール**：ゲームが前面にないときは「スクロールのためゲームを一時的に前面にします」というバナーを表示し、一時的にゲームを前面に切り替えてスクロールし、終わると元のウィンドウとカーソルを戻します。その間に自分でウィンドウを切り替えた場合、そのステップの残りのスクロールは中止し、選んだウィンドウを維持したまま、元のウィンドウにフォーカスを戻すこともしません。ゲームがすでに前面にある場合はそのままスクロールします。
- **マウス保護**（任意）：「ローカル操作モード」を展開すると「再試行に失敗した場合はマウスを一時的にロック」をオンにできます（既定はオフ）。干渉が繰り返されたときだけ物理マウスを一時的にブロックし、キーボードと一時停止・停止のホットキーは使えるままです。1 回あたり最大 2 秒で、操作の終了、一時停止、停止、異常発生時にはすぐに解除されます。保護中の長押しやドラッグが 2 秒を超えた場合は押下状態を解除し、タスクが画面を確認し直します。
- 座標を指定しない通常攻撃はフィールド視点のカーソル固定を認識し、前の画面のクリック位置を使い回さずに、現在の位置でそのまま押して離します。
- 自動会話は GUI の中で動作します。マウスの使用中やウィンドウが一時的に使えないときは短く待つだけで次のチェックに任せるため、画面が固まることはありません。

### ウィンドウ状態の変化

- **ウィンドウの切り替え**：ゲームを前面にしたり他のウィンドウに切り替えたりするのは通常の操作で、そのためにタスクがエラーで終了することはありません。入力の途中だった場合は、その入力で押していたキー、マウス、一時的な保護を先に解除してから、タスクがゲーム画面を認識し直します。すでに送信したキー、テキスト、クリック、ドラッグが自動で再実行されることはありません。
- **最小化または一時的に非表示**：入力は一切送信せず、スクリーンショットと入力は最大 60 秒待機して、ゲームウィンドウを元に戻すよう案内します。元に戻すと自動で続行し（待機中に保留した入力は未完了として返し、後から送信しません）、タイムアウトした場合は理由を示してタスクを停止します（ログ例：「游戏窗口已最小化（已等待 60 秒）」＝ゲームウィンドウが最小化されています（60 秒待機））。同じ使用不能の期間中に待機するのは 1 回だけで、一時停止中の時間は待機時間に含めません。プログラムがゲームウィンドウを自動で元に戻したりアクティブにしたりすることはありません。
- **ゲームプロセスの終了**：待機せずにすぐ「游戏进程已退出」（ゲームプロセスが終了しました）と報告し、ウィンドウを元に戻すようには案内しません。ゲーム起動の段階ではフォアグラウンドモードと同様にゲームを閉じて再起動し、タスクの途中では通常のエラーとして終了します。
- **プロセスはあるのにゲームウィンドウが見つからない場合**（ゲームの起動中やウィンドウの再作成中など）：同様に最大 60 秒待機し、タイムアウトした場合は通常のエラーとして扱います。
- **ゲームが読み込み中で応答しない場合**：マウスメッセージが 0.5 秒以内に処理されないときは、その入力を解除して未完了として返し、タスクが画面を確認し直します。これによってタスクが終了することはありません。
- 入力の途中でウィンドウが移動したりサイズが変わったり、座標がゲーム画面の外になったりした場合も、同様に入力を解除して未完了として返します。

「未完了」は、その入力が最後まで送信されなかったことだけを意味します。最後まで送信済みで、終了待ちの間にウィンドウの切り替えや一時停止があっただけの操作は成功として返すため、すでに反映されたクリックやキー入力をタスクがもう一度実行することはありません。

### 一時停止と停止

一時停止と停止では、まずバックエンドが押しているキーとマウスを解除し、一時的な前面操作を終えてから状態を返します。一時停止から再開しても、中断された長押しやドラッグは再実行しません。現在の画面を確認してから続行してください。GUI からタスクを停止すると、まず停止コマンドを送り、「入力を解除した」という応答を待ってからプロセスを終了します。時間内に応答がない場合は従来どおり強制終了し、ログに記録します。コマンドラインの `--control <実行 ID> stop` も同じコマンドを使います。

### 既知の制限

- ランチャーや、単独で動作するフィールド探索、サードパーティ製の模擬宇宙などのプログラムはバックグラウンド動作に対応しません。それぞれの要件に従ってフォアグラウンドで実行してください。
- マウスを使い続けている間、クリックが必要な手順はマウスが止まるまで待ち続けます。マウス保護がブロックするのは物理マウスだけで、操作を続けている間にクリックが完了することは保証できません。
- テキスト入力は、同じアクティブ化セッションの中で直前に位置を特定した入力欄をもう一度クリックしてから文字を送信します。IME の変換候補や、任意のエディタへの追記には対応していません。
- 貨幣戦争の報酬オーブは短い区間ごとにスワイプし、区間ごとにマウスを離します。途中の手順が完了しなかった場合は現在の段階を維持して次のラウンドで確認し直し、そのまま購入や出撃には進みません。
- 認識や操作の異常が起きた場合は、まずフォアグラウンドモードに戻して問題がバックグラウンドモードに関係するか確認し、ログを添えて報告してください。

## クラウド・崩壊：スターレイル

`クラウド・崩壊：スターレイル` を有効にすると、開拓力消化、デイリー訓練、貨幣戦争、差分宇宙などのタスクは固定ウィンドウが不要になり、バックグラウンド実行に対応し、ウィンドウなしでも実行できます。フィールド探索と模擬宇宙は引き続き前面全画面が必要です。

クラウドゲームはローカルのゲームウィンドウに依存せず、macOS、Linux、[Docker](/assets/docs/Docker.md)、[Termux（Android）](/assets/docs/Termux.md) でも実行できます。有効にする方法は [利用ガイド](/assets/docs/Tutorial_ja_JP.md) を参照してください。

## リモートローカル多ユーザーデスクトップ（上級者向け）

> 同じパソコン上で（2 台目のパソコンは不要）ローカルのリモートデスクトップから別の Windows ユーザーセッションにサインインし、そのセッションでゲームとアシスタントをフォアグラウンドモードで動かします。現在のデスクトップのキーボードとマウスはまったく使いません。複数ユーザーの同時サインインを許可するためにシステムへパッチを当てる必要があり、設定が複雑で、システム更新後にパッチが無効になることもあります。通常は Windows バックグラウンドモードを優先してください。

 * エミュレーターでの実行は動作が重く、リソース消費も大きいなど多くの欠点があり、パソコン上で直接実行するほうが負荷は小さくなります
 * Windows に標準搭載のリモートデスクトップサービスの利用をおすすめします
 * Windows でリモートデスクトップの複数ユーザーを有効にする手順（中国語）：
   * [詳細な手順 by_Rin](https://www.bilibili.com/read/cv24286313/)（⭐おすすめ⭐）
   * [RDPWrap を使う方法](https://blog.sena.moe/win10-multiple-RDP/)
   * [ファイルを変更する方法](https://www.wyr.me/post/701)
 * [詳細な手順 by_Rin](https://www.bilibili.com/read/cv24286313/) で使うすべてのファイル：[ダウンロードリンク](https://github.com/CHNZYX/asu_version_latest/releases/download/RDP/LocalRemoteDesktop1.191_by_lin.zip)
   * 予備リンク
     * [百度網盤](https://pan.baidu.com/s/13aoll4n1gmKlPT9WwNYeEw?pwd=jbha) 抽出コード：jbha
     * [GitHub ミラー](https://github.kotori.top/https://github.com/CHNZYX/asu_version_latest/releases/download/RDP/LocalRemoteDesktop1.191_by_lin.zip)

アシスタントをリモートセッションで実行している間は、リモートデスクトップ接続を開いたままにし、セッションを切断しないでください。既定では、リモートデスクトップのウィンドウを最小化するとリモートセッションの描画が止まり、スクリーンショットに失敗することがあります。最小化したい場合は、現在のユーザーのレジストリ `HKEY_CURRENT_USER\Software\Microsoft\Terminal Server Client` に DWORD 値 `RemoteDesktop_SuppressWhenMinimized` を作成してデータを `2` にし、リモートデスクトップ接続を開き直してください。

### Windows 11 をお使いの方へ

[詳細な手順 by_Rin](https://www.bilibili.com/read/cv24286313/) で紹介されている `SuperRDP` は使えなくなっている可能性があるため、代わりに [TermsrvPatcher](https://github.com/fabianosrc/TermsrvPatcher) をおすすめします。中国国内からは予備リンク [蓝奏云](https://wwsj.lanzout.com/i4V8u2np8dna) からもダウンロードできます。

**注意：** この方法で実現できるのは [詳細な手順 by_Rin](https://www.bilibili.com/read/cv24286313/) のうち `4. 多用户同时登陆补丁`（複数ユーザー同時サインインのパッチ）の部分だけです。残りの手順は元の手順に従ってください。

**使い方：**

1. `git clone` でリポジトリをクローンするか、圧縮ファイルを直接ダウンロードします。
2. ダウンロード後に展開し、`TermsrvPatcher.ps1` を右クリックして「実行」を選ぶと、スクリプトがすべての処理を自動で行います。

手動でファイルを変更したい場合は、ブログ記事 [ファイルを変更する方法](https://www.wyr.me/post/701) を参考にできます。ただし、記事内の一部の操作は Windows 11 では当てはまらない場合があります。

- **Windows 11 で検索する文字列（正規表現）：**
   `39 81 3C 06 00 00 0F (?:[0-9A-F]{2} ){4}00`（実際には `39 81 3C 06 00 00 0F` を検索すれば十分です。残りの 16 進数が正規表現に一致する場合だけ変更してください）
- **置き換える文字列：**
   `8B 81 38 06 00 00 39 81 3C 06 00 00 75`
