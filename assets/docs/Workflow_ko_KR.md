# 워크플로우 편집 사용법

> 이 문서는 중국어 간체 버전을 바탕으로 AI가 번역했습니다. 최종 갱신일: 2026-09-24. 차이가 있을 경우 중국어 간체 버전을 우선해 주세요.

## 어떤 상황에 적합한가

워크플로우 편집은 다음과 같은 작업에 적합합니다.

- 고정된 화면에서의 반복 클릭.
- 조건에 따라 분기해야 하는 간단한 자동화.
- 반복 감지, 화면 전환, 키 입력, 대기, 알림 등을 조합한 동작.
- 흩어진 조작을 반복해서 재사용할 수 있는 작은 워크플로우로 묶고 싶을 때.

이미 홈 화면의 기존 작업(개척력 소모, 데일리 훈련, 차분 우주 등)으로 충분하다면 그것을 먼저 사용하세요.

워크플로우 편집은 "나만의 보조 로직"을 만들 때 적합합니다.

## 기본 개념

하나의 워크플로우는 여러 단계로 구성되며, 단계는 트리 구조로 관리됩니다.

- 일반 단계: 순서대로 실행합니다. 예: 이미지 클릭, 텍스트 클릭, 대기, 키 누르기.
- 마우스 단계: 고정 좌표 클릭을 지원하고, 왼쪽 버튼을 누른 채 시작점에서 끝점으로 드래그하는 것도 지원합니다.
- 제어 단계: 하위 단계를 가질 수 있습니다. 현재 `if`, `for`, `while`을 지원합니다.
- 반복 제어 단계: 반복 내부에서 `break`와 `continue`를 사용할 수 있습니다.

코드를 직접 작성하지 않아도 되는 "작은 비주얼 스크립트 편집기"라고 생각하면 됩니다.

## 진입 경로

어시스턴트를 실행한 뒤 왼쪽 내비게이션 바에서 "워크플로우 편집"으로 들어갑니다.

화면은 크게 두 부분으로 나뉩니다.

- 위쪽: 워크플로우 목록, 실행, 중지, 가져오기/내보내기, 템플릿 수집 등의 조작.
- 아래쪽: 단계 트리. 현재 워크플로우의 단계 구조를 편집합니다.

## 첫 워크플로우 만들기

### 새 워크플로우

"새 워크플로우"를 클릭하고 알아보기 쉬운 이름을 입력합니다.

공식 예시 워크플로우는 보통 읽기 전용이라 확인만 가능하고 직접 수정할 수 없습니다.

직접 만든 워크플로우는 편집, 이름 변경, 삭제, 내보내기가 가능합니다.

### 단계 추가

"단계 추가"를 클릭하면 현재 계층에 단계를 추가할 수 있습니다.

`if`, `for`, `while` 같은 제어 단계를 선택한 상태라면 "하위 단계 추가"로 그 노드 아래에 새 단계를 붙일 수 있습니다.

### 편집과 순서 조정

- 단계를 더블클릭하거나 "단계 편집"을 클릭하면 해당 단계를 수정할 수 있습니다.
- "위로 이동", "아래로 이동"으로 같은 계층의 단계 순서를 바꿀 수 있습니다.
- 단계 트리를 오른쪽 클릭하면 워크플로우 전체를 실행하거나 선택한 단계만 실행할 수 있습니다.

## 자주 쓰는 단계 설명

### 이미지 클릭

화면에 안정적인 버튼, 아이콘, 안내 창이 있을 때 적합합니다.

자주 쓰는 설정 항목:

- 템플릿 경로: 매칭에 사용할 이미지 소재.
- 이미지 임계값: 매칭 정밀도.
- 검출 영역: 지정한 영역 안에서만 이미지를 찾아 오인식을 줄일 수 있습니다.
- 재시도 횟수: 찾지 못했을 때 반복하는 횟수.
- 클릭 동작: 클릭, 누르기, 떼기.
- 누름 시간: 길게 눌러야 할 때만 입력합니다. 비워 두거나 0이면 기본 클릭 동작이 됩니다.

### 텍스트 클릭

버튼 글자는 안정적이지만 아이콘 모양이 자주 바뀌는 상황에 적합합니다.

자주 쓰는 설정 항목:

- 대상 텍스트: OCR로 인식할 글자.
- 포함 매칭 사용: 대상 텍스트 앞뒤에 다른 내용이 붙을 수 있을 때 사용합니다.
- 검출 영역: OCR 인식 범위를 제한합니다.
- 재시도 횟수: 찾지 못했을 때 반복합니다.
- 클릭 동작, 누름 시간: 이미지 클릭과 같습니다.

### 좌표 클릭

목표 위치는 고정되어 있지만 안정적으로 인식할 이미지나 텍스트가 없을 때 적합합니다.

보통 캡처 도구로 먼저 영역을 선택한 뒤, 그 좌표를 단계에 복사해서 넣습니다.

### 마우스 드래그

메뉴에서 목록을 드래그하거나, 게임 화면에서 왼쪽 버튼을 누른 채 마우스를 움직일 때 사용합니다.

- 드래그 시작점과 끝점은 게임 창을 기준으로 한 정규화 좌표를 사용합니다. 예: `100 / 1920, 540 / 1080`.
- 드래그 시간은 0~60초이며, 시작점에서 끝점까지 이동하는 속도를 결정합니다. 길수록 느리게 이동합니다.
- 실행 시 먼저 시작점으로 이동해 마우스 왼쪽 버튼을 누르고, 끝점으로 이동한 뒤 뗍니다.
- 클라우드 게임 모드는 브라우저 포인터 잠금 제한 때문에 이 단계로 시점을 돌릴 수 없습니다. 메뉴 드래그는 실제 게임에서 확인해야 합니다.

### 이미지 찾기 / 텍스트 찾기

이 두 단계는 클릭하지 않고 대상이 존재하는지만 판단합니다.

`if`나 `while`의 조건 판단에 자주 쓰입니다. 예:

- "도전 시작"이 감지됐을 때만 계속 클릭한다.
- 특정 경고 이미지가 감지되지 않는 동안 계속 반복하며 기다린다.

### 대기

가장 단순한 지연 단계입니다. 화면 전환, 애니메이션 재생, 버튼 표시 전에 여유를 둘 때 적합합니다.

### 키 누르기

키보드 입력을 시뮬레이션합니다. 클릭, 누르기, 떼기를 선택할 수 있고 키 누름 시간도 설정할 수 있습니다.

### 화면 전환

이 단계는 어시스턴트에 이미 있는 화면 전환 로직을 호출합니다.

선택 대상은 임의 입력이 아니라, 현재 프로그램에 정의되어 있고 `main` 메인 화면에서 능동적으로 전환할 수 있는 화면뿐입니다.

드롭다운 목록에 없는 화면은 현재 버전에서 직접 전환할 수 없습니다.

### 오디오 재생 / 알림 푸시

이 두 단계는 중요한 시점에 알려 줄 때 적합합니다.

- 오디오 재생: 로컬에서 알림음을 재생합니다.
- 알림 푸시: 현재 설정한 알림 채널로 텍스트를 보냅니다. 스크린샷을 함께 보낼 수도 있습니다.

## 제어 단계 사용법

### if

조건이 성립하면 그 아래의 하위 단계를 실행합니다.

"어떤 버튼이 보이면 그것을 누른다" 같은 로직에 적합합니다.

### for

정해진 횟수만큼 하위 단계를 반복합니다.

반복 횟수에 0을 넣으면 무제한 반복이 되며, 조건이나 중지 버튼, 또는 `break`로 끝내야 합니다.

### while

조건이 성립하는 동안 계속 하위 단계를 실행합니다.

조건이 비정상일 때 빠져나오지 못하는 것을 막기 위해 적절한 최대 반복 횟수도 함께 설정하는 것을 권장합니다.

### break / continue

이 두 단계는 반복 내부에만 둘 수 있습니다.

- `break`: 현재 반복을 종료합니다.
- `continue`: 이번 회차의 남은 단계를 건너뛰고 바로 다음 반복을 시작합니다.

반복 밖에 두면 실행 로그에 해당 단계가 무효라고 표시됩니다.

## 템플릿과 좌표 수집하기

### 이미지 템플릿 수집

"이미지 템플릿 수집"을 클릭하면 캡처 창이 열립니다.

영역을 선택한 뒤 저장하면, 템플릿은 현재 워크플로우 전용 소재 폴더에 자동으로 저장됩니다.

워크플로우 소재는 워크플로우와 함께 저장되며, 내보낼 때도 함께 묶입니다.

### 검출 영역 입력 방법

이미 캡처 도구로 영역을 선택했다면, 생성된 좌표식을 그대로 "검출 영역"에 붙여 넣을 수 있는 경우가 많습니다.

입력하지 않으면 기본값은 전체 화면 검색입니다.

안정성을 높이려면 대상이 나타날 수 있는 위치만 덮도록 검출 범위를 좁히는 것을 권장합니다.

## 실행과 디버깅

### 워크플로우 실행

"워크플로우 실행"을 클릭하면 현재 워크플로우의 모든 단계를 실행합니다.

워크플로우는 로그 화면의 독립 작업으로 실행되므로, 중지할 때는 로그 화면에서 강제 종료할 수 있습니다.

### 선택한 단계 실행

단계 트리에서 단계를 선택한 뒤 오른쪽 클릭 메뉴에서 "선택한 단계 실행"을 고를 수 있습니다.

이 기능은 특정 노드가 이미지, 텍스트, 좌표를 올바르게 인식하는지 확인할 때 매우 유용합니다.

### 로그 보는 방법

실행할 때는 로그 화면 출력을 중점적으로 확인하세요.

- 현재 몇 번째 단계를 실행 중인지.
- 조건 판단이 성공했는지.
- 최대 반복 횟수에 도달했는지.
- 예외, 템플릿 미검출, 대상 텍스트 미인식 등이 발생하지 않았는지.

## 가져오기, 내보내기와 소재 폴더

워크플로우는 폴더 형태로 저장되며 보통 다음을 포함합니다.

- `workflow.yaml`: 워크플로우 구조 본체.
- `templates/`: 이미지 템플릿 소재.

"워크플로우 내보내기"로 워크플로우 전체를 zip으로 묶어 공유할 수 있습니다.

"워크플로우 가져오기"로 자신의 어시스턴트에 복원할 수도 있습니다.

## 간단한 예시

흔히 쓰는 흐름을 소개합니다.

1. `if`로 텍스트 "도전 시작"을 감지한다.
2. 조건이 성립하면 하위 단계에서 "텍스트 클릭: 도전 시작"을 실행한다.
3. `wait`로 1초 대기한다.
4. `while`로 어떤 결산 안내가 아직 나타나지 않았는지 감지한다.
5. 반복 본문에서 매번 1초 대기하고, 최대 몇 회까지 실행한다.
6. 결산을 인식하면 오디오를 재생하거나 메시지를 보낸다.

먼저 워크플로우를 짧고 작게 만들어 각 단계가 안정적인지 확인한 뒤, 분기와 반복을 조금씩 추가하면 성공률이 더 높아집니다.

## 자주 하는 조언

- 검출 영역은 작게 잡으세요. 기본값인 전체 화면 이미지 검색이나 전체 화면 OCR은 피하세요.
- 이미지 템플릿은 안정적인 특징만 남기도록 잘라내고, 움직이는 배경을 함께 넣지 마세요.
- 텍스트로 인식할 수 있는 상황이라면 "텍스트 클릭"을 먼저 시도하세요.
- 단일 단계를 디버깅할 때는 "선택한 단계 실행"을 쓰고, 매번 워크플로우 전체를 실행하지 마세요.
- 인식 결과가 불안정하면 먼저 "도구 상자 → 게임 스크린샷"에서 프로그램이 가져오는 화면이 올바른지 확인하세요.
- 기존 작업을 자동화하려는 것뿐이라면 워크플로우 편집부터 시작하지 않는 것을 권장합니다. 유지보수 비용이 더 커집니다.
