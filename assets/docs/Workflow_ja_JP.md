# フロー編成の使い方

> このドキュメントは簡体字中国語版をもとに AI で翻訳しています。最終更新日: 2026-09-24。差異がある場合は簡体字中国語版を優先してください。

## どんな場面に向いているか

フロー編成は、次のような作業に向いています。

- 固定された画面での繰り返しクリック。
- 条件によって分岐する簡単な自動化。
- ループ検出、画面切替、キー入力、待機、通知などを組み合わせた動作。
- バラバラの操作を、繰り返し使える小さなフローにまとめたいとき。

すでにホーム画面の既存タスク（開拓力消化、デイリー訓練、差分宇宙など）で足りる場合は、そちらを優先してください。

フロー編成は「自分専用の補助ロジック」を作るのに向いています。

## 基本概念

1 つのフローは複数のステップで構成され、ステップはツリー構造で管理されます。

- 通常ステップ：順番に実行します。例：画像をクリック、テキストをクリック、待機、キーを押す。
- マウスステップ：固定座標のクリックに対応し、左ボタンを押したまま開始位置から終了位置へドラッグすることもできます。
- 制御ステップ：子ステップを持てます。現在は `if`、`for`、`while` に対応しています。
- ループ制御ステップ：ループの内部で `break` と `continue` を使用できます。

コードを書かずに使える「小さなビジュアルスクリプトエディター」だと考えてください。

## 入口

アシスタントを起動し、左側のナビゲーションバーから「ワークフロー編成」に入ります。

画面は大きく 2 つに分かれています。

- 上半分：フロー一覧、実行、停止、インポート／エクスポート、テンプレート取得などの操作。
- 下半分：ステップツリー。現在のフローのステップ構造を編集します。

## 最初のフローを作る

### 新しいフロー

「新しいフロー」をクリックし、分かりやすい名前を入力します。

公式のサンプルフローは通常読み取り専用で、閲覧のみ可能です。直接編集はできません。

自分で作成したフローは、編集・名前変更・削除・エクスポートができます。

### ステップを追加する

「ステップを追加」をクリックすると、現在の階層にステップを追加できます。

`if`、`for`、`while` などの制御ステップを選択している場合は、「子ステップを追加」でそのノードの下に新しいステップを追加できます。

### 編集と順序の入れ替え

- ステップをダブルクリックするか「ステップを編集」をクリックすると、そのステップを変更できます。
- 「上へ」「下へ移動」で、同じ階層のステップの順序を入れ替えられます。
- ステップツリーを右クリックすると、フロー全体の実行や、選択中のステップだけの実行ができます。

## よく使うステップの説明

### 画像をクリック

画面上に安定したボタン、アイコン、ダイアログがある場合に向いています。

よく使う設定項目：

- テンプレートパス：マッチングに使う画像素材。
- 画像しきい値：マッチングの精度。
- 検出範囲：指定した範囲内だけで画像を探すため、誤認識を減らせます。
- 再試行回数：見つからないときに繰り返す回数。
- クリック動作：クリック、押す、離す。
- 押下時間：長押しが必要なときだけ入力します。空欄または 0 の場合、通常のクリック動作になります。

### テキストをクリック

ボタンの文字は安定しているものの、アイコンの見た目が変わりやすい場面に向いています。

よく使う設定項目：

- 対象テキスト：OCR で認識する文字。
- 部分一致を使用：対象テキストの前後に余分な文字が入る可能性がある場合に使います。
- 検出範囲：OCR の認識範囲を限定します。
- 再試行回数：見つからないときに繰り返します。
- クリック動作、押下時間：画像をクリックと同じです。

### 座標をクリック

目標の位置は固定されているものの、安定して認識できる画像や文字がない場合に向いています。

一般的には、先にキャプチャツールで範囲を選択し、その座標をステップにコピーします。

### マウスをドラッグ

メニュー内でリストをドラッグしたり、ゲーム画面で左ボタンを押したままマウスを動かしたりする用途です。

- ドラッグ開始位置とドラッグ終了位置は、ゲームウィンドウを基準とした正規化座標で指定します。例：`100 / 1920, 540 / 1080`。
- ドラッグ時間は 0〜60 秒で、開始位置から終了位置へ移動する速度を決めます。長いほどゆっくり移動します。
- 実行時は、まず開始位置へ移動してマウスの左ボタンを押し、終了位置へ移動してから離します。
- クラウドゲームモードではブラウザーのポインターロック制限により、このステップで視点を回すことはできません。メニューのドラッグは実際のゲーム内で確認してください。

### 画像を検索 / テキストを検索

この 2 つのステップはクリックを行わず、対象が存在するかどうかだけを判定します。

`if` や `while` の条件判定によく使われます。例：

- 「挑戦を開始」を検出したときだけクリックを続ける。
- ある警告画像を検出しない間は、ループして待ち続ける。

### 待機

最も単純な遅延ステップです。画面切替、アニメーション、ボタンの表示前に余裕を持たせたいときに使います。

### キーを押す

キーボード入力をシミュレートします。クリック、押す、離すを選べ、キーの押下時間も設定できます。

### 画面切替

このステップは、アシスタント既存の画面切替ロジックを呼び出します。

選べる対象は自由入力ではなく、現在のプログラムで定義済みで、かつ `main` メイン画面から能動的に切り替えられる画面だけです。

ドロップダウンに無い画面は、現在のバージョンでは直接切り替えられません。

### 音声を再生 / 通知送信

この 2 つのステップは、重要な場面で知らせるのに向いています。

- 音声を再生：ローカルで通知音を鳴らします。
- 通知送信：現在設定している通知チャンネルにテキストを送信します。スクリーンショットを添付することもできます。

## 制御ステップの使い方

### if

条件が成立したときに、その下の子ステップを実行します。

「あるボタンが見えたらそれを押す」といったロジックに向いています。

### for

決まった回数だけ子ステップを繰り返します。

ループ回数に 0 を入力すると無制限のループになります。条件、停止ボタン、または `break` で終了させてください。

### while

条件が成立し続ける限り、子ステップを実行し続けます。

条件が異常なときに抜けられなくなるのを防ぐため、あわせて妥当な最大ループ回数を設定することをおすすめします。

### break / continue

この 2 つのステップはループの内部にのみ置けます。

- `break`：現在のループを終了します。
- `continue`：今回の残りのステップを飛ばして、次のループを開始します。

ループの外に置いた場合、実行ログにそのステップが無効である旨が表示されます。

## テンプレートと座標を取得する

### 画像テンプレートを取得

「画像テンプレートを取得」をクリックすると、キャプチャ画面が開きます。

範囲を選択して保存すると、テンプレートは現在のフロー専用の素材フォルダーに自動で保存されます。

フローの素材はフローと一緒に保存され、エクスポート時にもまとめて梱包されます。

### 検出範囲の入力方法

すでにキャプチャツールで範囲を選択している場合は、生成された座標式をそのまま「検出範囲」に貼り付けられることが多いです。

未入力の場合、既定では全画面検索になります。

安定性を高めるため、検出範囲は対象が現れる可能性のある位置だけに絞ることをおすすめします。

## 実行とデバッグ

### フローを実行

「フローを実行」をクリックすると、現在のフローのすべてのステップを実行します。

フローはログ画面の独立したタスクとして実行されるため、停止したいときはログ画面から強制終了できます。

### 選択したステップを実行

ステップツリーでステップを選択し、右クリックメニューから「選択したステップを実行」を選べます。

この機能は、あるノードが画像・テキスト・座標を正しく認識できるかを確認するのに最適です。

### ログの見方

実行時はログ画面の出力を重点的に確認してください。

- 現在どのステップを実行しているか。
- 条件判定が成功したか。
- 最大ループ回数に達したか。
- 例外、テンプレート未検出、対象テキスト未認識などが発生していないか。

## インポート・エクスポートと素材フォルダー

フローはフォルダーとして保存され、通常は次を含みます。

- `workflow.yaml`：フロー構造の本体。
- `templates/`：画像テンプレート素材。

「フローをエクスポート」でフロー全体を zip にまとめて配布できます。

「フローをインポート」で自分のアシスタントに復元することもできます。

## 簡単な例

よくある考え方を示します。

1. `if` でテキスト「挑戦を開始」を検出する。
2. 条件成立後、子ステップで「テキストをクリック：挑戦を開始」を実行する。
3. `wait` で 1 秒待機する。
4. `while` であるリザルト通知がまだ出ていないかを検出する。
5. ループ本体で毎回 1 秒待機し、最大で数回まで実行する。
6. リザルトを認識したら、音声を再生するかメッセージを送信する。

まずはフローを短く小さく作り、各ステップが安定するのを確認してから、少しずつ分岐やループを足していくと成功率が上がります。

## よくあるアドバイス

- 検出範囲は小さめに。既定の全画面検索や全画面 OCR は避けてください。
- 画像テンプレートは安定した特徴だけを残すように切り出し、動く背景を一緒に入れないでください。
- テキストで認識できる場面では、「テキストをクリック」を優先して試してください。
- 単一ステップのデバッグには「選択したステップを実行」を使い、毎回フロー全体を実行しないでください。
- 認識結果が不安定なときは、まず「ツールボックス → ゲーム画面キャプチャ」でプログラムが取得している画面が正しいか確認してください。
- 既存タスクを自動化したいだけなら、フロー編成から始めるのはおすすめしません。保守の手間が増えます。
