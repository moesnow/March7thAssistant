# 游戏优化与临时降低画质

在「设置 → 杂项 → 启用游戏优化」中展开配置三个独立选项：

- 启用自动战斗和二倍速检测。
- 启用自动修改分辨率并关闭自动 HDR。
- 任务期间自动降低画质，默认关闭，开启前会显示确认说明。

总开关默认开启，以兼容旧配置。升级时不改变原有两个子开关，关闭总开关也不会清除子开关的选择。总开关同时约束任务内的自动战斗检测和云游戏的启动设置；工具箱「自动对话」的独立配置不属于这组三项设置。

## 适用范围

临时画质仅在助手为任务启动 Windows 本地游戏时应用。已有游戏进程、云游戏、GUI 的手动「启动游戏」和 CLI 的 `game` 命令不会降低画质。直接启动和 Epic 启动使用相同的任务前置处理；不会为了应用或恢复画质重启游戏。

当前支持注册表版本 10 的自定义画质。请先在游戏内将「图像质量」设为自定义并保存。预设、未知版本、缺失/损坏的字段及 A/B 测试格式会记录原因并跳过，不猜测配置。

通过所选安装目录中的 `StarRail_Data/app.info` 确认公司和产品名称，分别定位国服/国际服注册表，不采用「找到国服就优先使用」的判断。文件缺失或身份未知时跳过，避免修改其它安装的设置。国服格式已通过只读现场数据核对；国际服与 Epic 路径通过替身测试，未进行游戏内验证。

只降低阴影、光照、角色、场景细节、反射和特效档位，不提高已经较低的选项。帧率、渲染比例、分辨率质量、抗锯齿、DLSS、泛光和未知字段保持原值。分辨率/HDR 仍由其独立开关控制。

## 恢复与边界

1. 修改前把原始二进制内容原子保存到当前用户的 `%LOCALAPPDATA%\March7thAssistant\temporary-graphics.json`。备份失败则不修改注册表。同一用户的不同安装共用备份和短时文件锁，避免并发任务互相覆盖。
2. 游戏完成启动加载后尽早恢复持久配置，任务结束再检查一次，保留自定义数据与原始字节。任务启动失败、重试、正常完成、取消、异常和循环等待都进入恢复流程；关闭游戏后、关机等系统操作之前也会恢复。
3. GUI 发现任务进程结束，以及下一次启动助手或通过助手手动启动游戏时，会检查已退出任务留下的备份。恢复不受当前总开关/子开关影响；仍存活的其它任务不会被干扰。任务结束但游戏还在运行时会保留备份，下次恢复检查确认游戏已退出后才移除，以便处理较晚的退出写回。
4. 只有注册表仍等于本次临时模型时才覆盖恢复。如果用户、游戏更新或其它程序改了设置，保留新配置和原始备份并在日志提示，不强行覆盖。恢复写入失败也会保留备份，供下次重试。

注册表不是游戏内实时画质接口。**运行中的游戏不会立即恢复画面，重启游戏后才应用原画质。** 任务完成后选择「不退出游戏」时也遵循这个行为。

强杀整个助手、断电等情况无法执行清理。如果发生在临时配置写入后、首次恢复前，下次应先打开助手恢复备份，再手动启动游戏。没有独立常驻恢复进程。恢复失败或冲突时请检查日志中给出的备份位置，不要删除原始备份。

## 验证

自动测试使用内存注册表和替身游戏控制器，不会修改真实游戏配置：

```powershell
python -m pytest tests/test_utils/test_temporary_graphics.py tests/test_tasks/test_graphics_lifecycle.py tests/test_app/test_graphics_settings.py
```

包括写前备份、原字节恢复、未知格式、已有游戏、重试、并发、失败保留、外部改动、任务退出与设置弹窗。尚未进行真实游戏运行验证，因此不能保证性能收益或所有任务的图像识别效果；遇到识别异常请关闭该选项。
