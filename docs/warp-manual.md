# 手动补充与更正抽卡记录

在「抽卡记录」页面点击「手动补充与更正」，会打开独立窗口。原来的统计页面、导入、导出、Excel、复制链接和清空仍保留。点击「更新数据」右侧的小箭头可以选择「更新完整数据」。

## 只记得以前的五星

1. 打开「手动补充」。没有记录时也可以使用，先填写游戏内的账号 UID。
2. 选择卡池，填写五星角色或光锥名称。出金抽数可以设为「未知」，日期可以留空。
3. 点击「添加并继续」。保存后输入框清空，可以紧接着填写下一个五星。
4. 选中列表中的项目后，可编辑、删除或上移/下移。顺序按旧到新排列。

每次保存立即生效。删除手填摘要不会删除真实抽卡记录。窗口关闭或按 Esc 时，如有尚未保存的填写内容，会先询问是否放弃。

## 更正已有五星的抽数

在「已有五星抽数」选择一条记录，填写正确抽数并点击「保存更正」。也可以明确设为「未知」。点击「撤销更正」会恢复按原始明细计算的结果，原始记录从未被修改或删除。

## 统计口径

- 明细总抽数和星级占比只使用真实逐抽记录。不会用手填抽数补造普通记录、游戏记录 ID 或时间。
- 没有手工数据时，显示和计算沿用原版：每个五星使用已保存明细中的间隔计数，包括首个五星，平均值也包含首个计数。不会自动把原始数值变为未知。
- 这些是记录内的抽数，不保证历史没有截断。知道实际抽数时，可在管理窗口更正；原始明细保持不变。
- 五星平均值使用记录内间隔、有效更正和补充五星的抽数。用户主动把某项设为未知后，该项显示 `?`，整体平均值也显示 `?`，不按零处理，也不把部分样本均值冒充整体均值。
- 混有补充五星时，总抽数简短标为「明细共」，真实五星数量及概率标为「5星明细」，合并历史仍自然展示。不会把摘要混入概率分母，也不增加独立说明标题。没有手工数据时不改变原有文案。
- 统计页沿用同一行彩色「名字[抽数]」历史，只有主动选择未知的抽数才显示 `?`。来源、编辑删除留在管理窗口，不在统计页逐项堆叠标记。
- 手填与真实五星合并展示：有日期时按日期插入，同日的手填按列表顺序放在当日明细之前；无日期的历史按列表顺序置于明细之前。这只是显示位置，不会给未知日期赋值。
- 日后找回完整明细时，不会仅凭同名、日期或抽数自动猜测哪些手填项重复。请自行核对并删除重复摘要。
- 更正只附着在相同 ID 且卡池、名称、时间、星级均匹配的真实记录上。原记录缺失或发生变化时，更正保留但不参与统计，可以在窗口中撤销。

## 导出与恢复

- **UIGF/SRGF**：只导出真实逐抽记录。标准无法表达仅有五星的摘要或抽数更正，因此有手工数据时会先提醒。
- **小助手完整备份**：包含原始明细、手填五星、排序、未知值和更正。存在手工数据时，保存窗口默认选择此格式。恢复时使用原来的「导入数据」按钮。
- **Excel**：保留原始明细表，另有五星统计和统计说明表。使用与页面相同的统计函数；空白抽数或日期表示未知。Excel 是查看用文件，不是完整恢复格式。

已有内容时，导入默认安全合并；不同账号不允许合并。只有明确选择强制替换并确认后，才能替换全部内容或换成另一个账号。确认窗口说明手填内容、更正的去留和数量。

「清空」会清空当前账号的明细、手填和更正，不会删除已导出的文件。如需恢复，请先导出完整备份。删除最后一条手填且没有真实明细或更正后，可以重新填写账号 UID。

## 维护与验证

手工数据放在 `warp.json` 的独立 `march7th_manual` 扩展中，而不是标准 `list`。其 `key` 只标识手填条目，不冒充游戏记录 ID。完整备份有独立格式标识和版本。

导入、抓取更新、手填编辑和清空统一使用跨进程文件锁、原文件快照检查、原子替换及原字节备份。过期窗口会报错，不能覆盖其他窗口已经保存的修改。清空留下空状态标记，防止此前启动的更新把旧记录写回来。其他不遵守该锁的外部编辑器不在互斥保证范围内。

测试入口：

```sh
uv sync --group dev
QT_QPA_PLATFORM=offscreen uv run pytest tests/test_app/test_warp_import.py tests/test_app/test_warp_import_gui.py tests/test_app/test_warp_export.py tests/test_app/test_warp_manual.py tests/test_app/test_warp_manual_gui.py
uv run python -m tools.i18n check
```

Windows/macOS 可省略 `QT_QPA_PLATFORM=offscreen`；需要显示实际测试窗口时添加 `--show-ui`。设置 `WARP_SCREENSHOT_DIR` 可保存真实 Qt 测试窗口的截图；所有示例账号与记录都是测试数据。
