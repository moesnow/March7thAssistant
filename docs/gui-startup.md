# 渐进式 GUI 启动

## 行为

主页与日志、工具服务先就绪。设置、帮助、抽卡记录、流程编排随后渐进预加载。日志页仍即时初始化任务、定时和热键；工具页仍按原配置恢复自动对话，不把运行服务的启动依赖于用户是否打开页面。

首次主页绘制后，预加载等待约 250 ms 开始。每轮以 6 ms 为协作预算，批间让出约 10 ms 给 Qt 事件循环。点击未准备好的页面会立即显示加载提示并提高其优先级；重复点击不重复构造。完成后原位替换占位页，用户若已切走，不抢回导航。失败只影响相应页面，可用“重试”按钮重试。

最小化到托盘且未绘制主页时，不额外预加载隐藏页面；任务、热键和定时服务仍正常初始化，显示主页或请求页面后开始预加载。

## 实现与维护约束

- `app/common/page_loader.py` 管理单一任务队列、请求优先级、构建预算、失败和取消。
- `SettingInterface`、`HelpInterface`、`WorkflowInterface` 的 `iter_build()` 在 GUI 主线程创建真实控件，构建过程中保持隐藏。直接实例化默认仍同步完成，兼容独立页面调用和既有测试。
- 设置页一开始即归属主窗口最终的 `stackedWidget.view`，保留单独的逻辑主窗口引用；设置分组一开始即归属设置页的 `QStackedWidget`，减少整棵控件树重复挂接和样式处理。
- 构建器只在完整的小步骤之间 `yield`。不要在 QThread 创建 QWidget，也不要用 `processEvents()` 使半构建页面重入。
- 配置内容、语言或主题发生变化时，丢弃尚未公开的旧构建并按最新状态重新构建；不重复初始化日志与工具服务。已完成设置页原有的语言切换/配置重载事务和失败回滚仍保留。
- 导航动画、模态/弹出窗口、语言或配置切换、桌面分身接管期间暂停预加载。替换页面不追加导航历史。导航回调读取当前页面实例，不捕获即将销毁的占位页。
- 退出前停止预加载、语言和配置定时器，关闭生成器并释放候选页面。设置页还释放尚未加入布局、暂时没有 Qt 父对象的卡片。
- 6 ms 是协作预算，不是强制抢占上限。单个控件构造、Markdown 渲染、抽卡记录/流程文件处理等操作仍可能超过预算。新增耗时步骤应继续拆分，或将纯数据准备移至工作线程，再由主线程应用结果。不能据此承诺固定帧率。

## 验证方式

```bash
uv sync --python 3.14.8 --frozen --all-groups
QT_QPA_PLATFORM=offscreen uv run pytest tests/ -q
uv run python -m tools.i18n check
```

`tests/test_app/test_progressive_startup.py` 覆盖真实 Qt 主线程分批、优先级与重复访问、配置代次失效、模态/动画暂停、局部失败重试、退出清理、加载中切页不抢焦点、配置/语言变化、帮助文档缺失、未挂接卡片释放以及最终真实页面完整性。

Windows/macOS 应使用各自原生 Qt 后端验证，不设置 Linux 的 offscreen 环境变量。
